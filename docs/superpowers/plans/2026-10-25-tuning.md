# Tuning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fourth "Tuning" tab sets the guitar's tuning. The Chord and Scale Compasses then draw the key's
notes in their true places: CAGED and positions still work for uniform shifts, while other tunings show
triads with inversions and the scale in fret windows.

**Architecture:**
- A tuning is six semitone offsets from standard, stored once (`nomad:tuning:v1`) and read by both compasses.
- Every theory function that uses `TUNING` takes the open-string pitches as a defaulted last parameter, so
  standard output and existing callers are unchanged.
- "Uniform" tunings (all offsets equal) just pass the real pitches into today's CAGED and position code.
- Other tunings switch the Chord Compass to a new `triadsOn` model and the Scale Compass to fixed fret
  windows.

**Tech Stack:** Next 15 static export, React 19, TS strict, Tailwind 3, Vitest + Testing Library (jsdom),
Playwright (`iphone` + `desktop`), pnpm.

**Spec:** `docs/superpowers/specs/2026-10-25-tuning-design.md`
(mockups: canvas page "Tuning").

## Global Constraints

- **Standard tuning is unchanged.** Every existing unit and e2e test passes without edits to its
  expectations (only call-site signature tweaks are allowed).
- **Storage.** A tuning is `offsets: number[6]` (low → high string), each an integer in **−5…+4**, and is
  stored in `nomad:tuning:v1`. Bad data reads as standard `[0,0,0,0,0,0]`.
- **Presets.** Exact values (name: offsets):
  - Standard: `0,0,0,0,0,0`
  - Half step down: `−1×6`
  - Whole step down: `−2×6`
  - Drop D: `−2,0,0,0,0,0`
  - DADGAD: `−2,0,0,0,−2,−2`
  - Open G: `−2,−2,0,0,0,−2`
  - Open D: `−2,0,0,−1,−2,−2`
  - Open C: `−4,−2,−2,0,1,0`
  - FACGCE: `1,0,−2,0,1,0`
- **Uniform tuning** means all six offsets are equal (this includes standard).
- **Tuning-tab spelling.** By pitch class: C, D♭, D, E♭, E, F, F♯, G, A♭, A, B♭, B. Inside the compasses,
  notes keep the key's spelling.
- **Triads.**
  - The bass is on the lowest of three adjacent strings, and the other two tones can sit on the other two
    strings in either order.
  - Frets run 0–15, and a triad is playable when max − min ≤ 4.
  - Sort by lowFret, then highFret, then inversion (root < first < second).
- **Scale fret windows:** `[0,4] [2,6] [5,9] [7,11] [10,15]`.
- **Selection defaults.** Triads default to `{ set: 2 (strings 4–3–2), inversion: "root" }`, and the scale
  window defaults to 0.
- **Tuning tab.**
  - Route `/tuning/`, tab label "Tuning".
  - No key slot: key-state's `TOOLS` stays `circle, chords, scales`.
  - No link toggle on this page.
  - `/` never redirects to it.
- **Accessibility and layout.** 44px tap targets, no horizontal scroll at 320–1440px, dark mode, VoiceOver
  labels. No new dependencies.

## Review Focus

1. **A non-standard tuning set before the compass mounts** (from storage) must render the right view on the
   first client render, with no flash of CAGED in DADGAD. (Task 6/7 e2e reload the page with DADGAD stored.)
2. **Switching tuning DADGAD → Standard → DADGAD** must keep the triad selection and the scale window (Task 7
   e2e).
3. **Changing the key in DADGAD** must keep the string set and inversion and pick the nearest triad (Task 3
   `resolveTriad` test).
4. **A custom tuning with no playable triad on a set** must disable that set's chip, not crash (Task 3 test
   with offsets `0,0,0,−5,3,0`, plus a Task 7 unit render).
5. **`/` after visiting Tuning** still opens the last *tool* (Task 4 unit test on `pageFromPath` /
   last-tool).

### Task 3: Triads and inversions on three strings

**Files:**
- Create: `lib/theory/triads.ts`, `lib/chords/triad-store.ts`, `lib/chords/use-triad-selection.ts`
- Test: `tests/unit/triads.test.ts`

**Interfaces:**
- **Consumes** `toneAt`, `ChordTone`, `Quality`, `MAX_FRET` (fretboard.ts), `nearestByCentre`
  (`lib/chords/neck-geometry.ts`), and `openPitches` (Task 1).
- **Produces:**
  - `type Inversion = "root" | "first" | "second"`
  - `type StringSet = 0 | 1 | 2 | 3`, the index of the lowest string. 0 = strings 6–5–4, 3 = strings 3–2–1.
  - `type Triad = { set: StringSet; inversion: Inversion; frets: [number, number, number]; tones: ChordTone[]; lowFret: number; highFret: number }`,
    with `frets` and `tones` running low string → high string.
  - `triadsOn(chord: readonly SpelledNote[], quality: Quality, open: readonly number[], set: StringSet): Triad[]`
    returns every playable triad on that string set, sorted per Global Constraints.
  - In `lib/chords/triad-store.ts`: `type TriadSelection = { set: StringSet; inversion: Inversion; centre: number | null }`,
    with default `{ set: 2, inversion: "root", centre: null }`, plus `parseTriadSelection(raw)` and
    `triadStore` (key `nomad:chords:triad:v1`). `resolveTriad` and `selectionFor` below live there too.
  - `useTriadSelection(): [TriadSelection, (s: TriadSelection) => void]`
  - `resolveTriad(triads: Triad[], sel: TriadSelection): Triad | null`, which works like this:
    - no triads → `null`;
    - otherwise take the triads with `sel.inversion`;
    - if there are none, return `triads[0]`;
    - if `centre` is null, return the first one;
    - otherwise return the one `nearestByCentre(…, centre)` picks.
  - `selectionFor(t: Triad): TriadSelection`, which returns `{ set, inversion, centre: (low+high)/2 }`

describe("triadsOn", () => {

  it("keeps the inversion and picks the nearest window", () => {

    expect(resolveTriad(all, { set: 0, inversion: "first", centre: null })!.frets).toEqual([4, 0, 0]);

    expect(resolveTriad([], { set: 2, inversion: "root", centre: null })).toBeNull();

  it("records a triad's selection", () => {

  });
  it.each([null, "{x", JSON.stringify({ set: 9, inversion: "root", centre: null })])("reads %s as the default", (raw) => {
    expect(parseTriadSelection(raw)).toEqual({ set: 2, inversion: "root", centre: null });
  });
});
